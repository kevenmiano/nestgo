# ADR — Hybrid static/dynamic execution and compilation overhead (GSD)

Status: Proposed / first implementation slice. Related: #24, #35, #36, #37, #38.

## Discuss

Do not remove dynamic reflection. Preserve interface-based injection, dynamically supplied metadata and current `runtime.New` semantics. Prefer static compilation of known metadata/handler plans, with reflection fallback for open-world cases. Current compiler generates ordinary Go but request handlers still use `reflect.Call`. Any compiler optimization must measure incremental build cost, generated bytes, binary size and build memory—not just request latency.

## Plan

1. **Baseline**: report `ns/op`, `B/op`, `allocs/op` for cold process start, warm `runtime.New`, 1/10/100/1000 providers, and HTTP request dispatch. Compare with `net/http` using the same response semantics. Record Go version, platform, SHA, CPU, fixture manifest and samples.
2. **Static injector optimization**: cache resolved interface types at startup. Keep dynamic `reflect.Implements` resolution when no precomputed binding exists; preserve missing/ambiguous detection.
3. **Compiler experiment**: generate optional typed route wrappers and provider factories for statically understood types and handlers. Explicit fallback for dynamic routes and interfaces. Compare behavior with golden tests before enabling by default.
4. **Build overhead**: for 1/10/100/1000 routes/providers, measure clean and no-op incremental `.mgo` compilation, Go build time, peak RSS, generated source bytes, binary bytes, and cold boot; isolate compiler stages. Avoid building test fixtures inside timed runtime benchmark loops.
5. **Scale**: benchmark HTTP with 1/2/4/8 replicas at fixed traffic and saturation; record throughput, CPU, p50/p95/p99 latency, GC cycles, heap, readiness and startup. Keep databases and network dependencies outside the first framework-only test.

## Execute — first slice

`runtime.New` now caches interface-to-provider matches for the lifetime of a single handler construction. Exact pointer matches still use a direct map lookup. There is **no persistent global cache**, no new metadata contract, and no removal of reflection. `runtime/performance_test.go` adds startup fixture scaling, dynamic ambiguity regression and HTTP comparison microbenchmarks.

## Verify

```bash
gofmt -w runtime/runtime.go runtime/performance_test.go
go test ./runtime -count=1
go test ./runtime -run '^$' -bench 'BenchmarkStartupProviders|BenchmarkHTTPRequest' -benchmem -count=10 > after.txt
go test ./... -count=1
go vet ./...
```

Compare `after.txt` against a baseline from `main` with the *same* benchmark definitions and environment. Use `benchstat` for statistical comparison, not single runs. The HTTP benchmark uses `httptest.ResponseRecorder`, so it isolates handler overhead rather than socket/network overhead. No measured speedups or production scale certification are claimed in this iteration.

Correctness gates: injection ambiguity, duplicate providers, missing handlers and HTTP behavior must not regress. Performance gates: log regressions with variance, avoid brittle universal millisecond thresholds.

## Review

This first slice does NOT generate static handler invokers, does not benchmark the compiler pipeline, and has not yet been verified by CI. It is a compatibility-preserving foundation to measure optimization choices, not completion of #35/#37 or production readiness.

## Ship

Only merge after CI checks and review. Keep related issues open until compiler-overhead matrix, typed wrappers, dynamic fallbacks and measured scalability tests are implemented.
